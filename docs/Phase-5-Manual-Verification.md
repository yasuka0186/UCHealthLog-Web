# Phase 5 手動確認手順

実データを使わず、架空の記録と非個人画像だけで確認する。確認前に設定画面から必要なデータをバックアップし、既存データを削除しない。

## macOS Safari

1. 専用オリジンの公開URLをSafariで開き、ライト／ダークモードで文字と操作要素を確認する。
2. 新しい日付へ架空の記録を保存し、再読み込み後も内容が残ることを確認する。
3. 同じ日付を更新し、履歴が重複せず更新されることを確認する。
4. 履歴から詳細を開き、編集保存できることを確認する。
5. 非個人画像を選択し、保存・詳細表示・同じ食事区分での置換を確認する。
6. グラフの7日・14日・30日を切り替え、未来日の記録が集計されないことを確認する。
7. ZIPをエクスポートし、新しいSafariプロファイルなど既存データのない環境へインポートして記録と写真を確認する。
8. 縦横のウィンドウ幅を変更し、横スクロールや操作不能がないことを確認する。
9. Safariを終了して再度開き、記録と写真が残ることを確認する。
10. 開発者ツールのネットワークで、健康記録や写真の外部送信がないことを確認する。

## iPhone Safari

1. 専用オリジンの公開URLをSafariで開き、ライト／ダークモードの両方を確認する。
2. 架空の記録について、新規保存、再読み込み、同日更新、履歴、詳細編集を確認する。
3. 非個人画像について、写真ライブラリまたはカメラからの選択、保存、表示、置換を確認する。
4. 7日・14日・30日グラフと未来日の除外を確認する。
5. ZIPのエクスポートと、既存データのない検証環境へのインポートを確認する。
6. 画面を縦向き・横向きに回転し、横スクロールや操作不能がないことを確認する。
7. Safariを終了して再度開き、記録と写真が残ることを確認する。

## 公開後の共通確認

- `/`、`/history`、`/graph`、`/settings`、`/privacy`を直接開いて表示できる。
- 実在する記録IDの`/history/:id`を直接開いて表示できる。
- レスポンスに`public/_headers`で指定したCSPなどのヘッダーが付く。
- Production source map、秘密情報、テスト成果物が公開されていない。
- 公開先はWordPressなどと共有しない専用オリジンである。
